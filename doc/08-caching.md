# Кэширование шаблонов

## Назначение

Компиляция шаблона (лексер → парсер → компилятор) выполняется на каждый рендеринг, если результат нигде не сохранён. Кэш избавляет от повторной компиляции одного и того же файла на каждый запрос: скомпилированный PHP-код один раз сохраняется на диск и затем просто подключается через `include`, пока не истечёт TTL или не изменится исходник.

## Как работает кэш

Кэшируется **скомпилированный PHP-код шаблона** (результат `compileFile()`), а не HTML-вывод — значит, переменные контекста всё равно подставляются заново при каждом запросе, кэшируется только сам процесс лексинга/парсинга/генерации кода. Кэш создаётся при первом обращении к файлу через `TemplateEngine::includeFile()`: если актуальной записи ещё нет, шаблон компилируется и результат записывается на диск, после чего сразу подключается. Инвалидация — по двум независимым условиям: истечение TTL и изменение mtime исходного файла (кэш, который старше исходника, считается недействительным даже если TTL ещё не истёк). Для кеширования используется `Vasoft\Joke\Cache\FileRelatedCache`. 

## Где хранится кэш

Базовая директория — `var/cache/templator/` (`FileSystem::atCache('templator')`), не настраивается отдельно для шаблонизатора — только через общий путь `var/` приложения. Имя файла строится из MD5-хеша полного пути к исходному шаблону, с разбиением на подкаталоги по первым двум символам хеша (чтобы не копить тысячи файлов в одной директории):

```
var/cache/templator/{первые 2 символа md5}/{полный md5}.php
```

Каталог создаётся автоматически при первой записи с правами `0755`; веб-серверу (`www-data`, `php-fpm`) нужны права на запись в `var/cache/`.

## Настройка TTL

TTL передаётся в секундах третьим аргументом `show()`/`includeFile()`:

```php
$response->show('pages/index.php', $context, 86400); // сутки
$response->show('pages/index.php', $context, 0);     // без кэша
```

`ttl=0` фактически отключает кэш: `exists()` сравнивает время создания файла с `time() - ttl`, и при `ttl=0` эта граница совпадает с текущим моментом — уже существующий (созданный раньше) файл всегда считается устаревшим, поэтому компиляция происходит заново на каждый запрос. Отключайте кэш на время активной разработки шаблонов и включайте разумный TTL (часы или сутки) в production.

Для файла каркаса, подключаемого директивой `{% layout %}`, TTL страницы (третий аргумент `show()`) не используется — вместо него берётся `TemplatorConfig::$defaultTtl` (по умолчанию 86400, настраивается через `setDefaultTtl()`, см. [Конфигурация шаблонизатора](09-configuration.md#ttl-каркаса-по-умолчанию)). У страницы и её каркаса, соответственно, может быть разный TTL кэша.

## Влияние на производительность

В production держите TTL ненулевым — компиляция шаблона заметно дороже `include` готового PHP-файла. В development удобнее `ttl=0`, чтобы правки в шаблоне сразу отражались на странице. Проверить, что кэш реально работает, просто: после первого запроса появляется файл в `var/cache/templator/{хеш}/...php` — при `ttl=0` он тоже создаётся, но перезаписывается на каждый запрос (обновляется `mtime`).
