# Каркасы и наследование шаблонов

## Назначение

Темы и каркасы (layouts) позволяют вынести общую разметку (обвязку страницы, подключение стилей) в отдельные файлы и
переиспользовать её на множестве страниц через директиву `{% layout %}` (синтаксис —
в [Описании директивы каркасов](04-directives/04-layout.md)). Несколько тем с одинаковой структурой каталогов дают
возможность иметь разное оформление (например, `default` и `dark`) без дублирования логики страниц.

## Структура директорий тем

Реальная структура демо-проекта:

```
templates/
├── default/                    # тема по умолчанию (TemplateEngine::DEFAULT_TEMPLATE)
│   ├── config.php              # PHP-хук темы (подключение общих ассетов)
│   ├── assets/styles.css
│   ├── layouts/
│   │   ├── main.php            # {% layout main %}
│   │   ├── main.css / main.js  # ресурсы каркаса main
│   │   └── note.php            # {% layout note %} — облегчённый каркас
│   └── components/
│       └── vasoft/random/default/template.php
├── dark/                        # дополнительная тема (без своих layouts/)
│   ├── config.php
│   ├── assets/styles.css
│   └── components/vasoft/random/variant1/
└── components/                  # общие шаблоны компонентов вне тем (fallback последнего уровня)
    └── vasoft/day/default/template.php
```

Каркас — файл `layouts/{имя}.php` внутри каталога темы. Обратите внимание: у темы `dark` в демо своей директории
`layouts/` вообще нет — это намеренно демонстрирует каскад ниже.

## Каскад поиска каркасов

`TemplateEngine::getLayoutPath()` ищет файл в двух местах, в этом порядке:

1. `templates/{активная тема}/layouts/{имя}.php`
2. Если не найден **и** активная тема не `default` — `templates/default/layouts/{имя}.php`

Если файл не найден ни там, ни там — `TemplatorException: Unable to locate layout file`. Третьего уровня fallback (как у
компонентов, где есть ещё и `getDefaultTemplatePath()`) для каркасов нет.

Пример на реальных данных: активная тема — `dark`, вызывается `{% layout main %}`.

```
1. templates/dark/layouts/main.php     — не существует (у dark нет layouts/)
2. templates/default/layouts/main.php  — найден, используется он
```

Так каркас `main`, написанный один раз для `default`, автоматически обслуживает и тему `dark`, пока в `dark/layouts/` не
появится собственный `main.php`, который его переопределит.

## Базовый каркас (layout)

`templates/default/layouts/main.php`:

```html

<fieldset>
    <legend>{%defer page.title%}</legend>
    {%raw __layout.content%}
    {%include css __layout.css%}
    {%include js __layout.js%}
</fieldset>
```

Единственная точка вставки контента — `{% raw __layout.content %}` - весь контент дочернего шаблона подставляется
целиком. `{% include css __layout.css %}`/
`{% include js __layout.js %}` подключают файлы `main.css`/`main.js`, лежащие рядом с каркасом. Директива `{% csrf %}` в
каркасе не нужна — она используется внутри конкретных форм на страницах, а не в общей обвязке.

## Дочерний шаблон

```html
<h1>{{ name }}</h1>
{% layout main %}
<p>Содержимое страницы</p>
{% /layout %}
```

Имя каркаса указывается **без кавычек** — `main`, а не `'main'` (кавычки буквально попадут в имя файла и сломают поиск).

## Вложенные каркасы

Отдельного механизма «каркас наследует каркас» нет, но поскольку `{% layout %}` — это обычная директива, она может
встретиться внутри содержимого другого `{% layout %}` (или внутри шаблона компонента, который сам оборачивается в лёгкий
каркас). Реальный пример из демо — компонент оборачивает свой вывод в отдельный каркас `note` (
`templates/default/layouts/note.php`, без заголовка и подключения ресурсов):

```html

<div class="variant2">
    {%layout note%}
    <h5>Вариант 2</h5>
    <p>Случайное число: {{demo}}</p>
    {%endlayout%}
</div>
```

Для сценария «базовый каркас сайта + отдельный каркас админки с сайдбаром» подход тот же: `layouts/admin.php` внутри
себя оборачивает свой контент в `{% layout main %}`, добавляя сайдбар до или после `{% raw __layout.content %}` своей
собственной обёртки — страница админки в этом случае ссылается на `{% layout admin %}`, а `admin.php` уже сам подключает
`main`.

## Переопределение блоков

Не поддерживается: система построена вокруг единственного слота `__layout.content`, а не именованных блоков с
переопределением/`append`/`prepend`. Если нужно управлять несколькими независимыми зонами страницы (например, сайдбар и
основной контент отдельно), варианты — несколько вложенных каркасов (как выше) либо отдельные переменные контекста,
которые каркас выводит через `{{ }}`/`{% raw %}` напрямую.
