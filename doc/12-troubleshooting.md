# Решение проблем

## Назначение

Как распознать и устранить типовые ошибки шаблонизатора по тексту исключения и стеку вызовов.

## Типовые ошибки и их решения

### 1. Ошибки компиляции (CompileException / ParserException / LexerException)

- **Симптом**: исключение вида `Directive 'if' with no arguments.`, `Unclosed tag(s): 'if'.` или `Unclosed tag "{%" found at position 12:4.`
- **Причина**: незакрытая директива (`{% if %}` без `{% /if %}`), пустой аргумент там, где он обязателен, незакрытый тег `{{`/`{%`.
- **Решение**: все три класса (`LexerException`, `ParserException`, `CompileException`) наследуют `TemplatorException` и не оборачиваются в общее сообщение, если возникли внутри `compileString()` — значит текст исключения уже указывает на конкретную причину. `LexerException` дополнительно даёт строку и колонку в исходном файле шаблона — по ним ищите незакрытый тег. Проверьте парность `{% %}`/`{% / %}`.

### 2. «Unable to locate...» — не найден layout, компонент или шаблон

- **Симптом**: `TemplatorException: Unable to locate layout file: main.` или `Unable to locate template 'variant2' for 'vasoft:random'.`
- **Причина**: файла нет ни в активной теме, ни в `default` (для layout — два уровня каскада; для компонентов — три, включая `getDefaultTemplatePath()`, см. [Каркасы и наследование шаблонов](06-layouts-and-inheritance.md)).
- **Решение**: проверьте, что файл `templates/{тема}/layouts/{имя}.php` (или `components/{vendor}/{name}/{templateName}/template.php`) существует. На Linux регистр букв в пути имеет значение — `Main.php` и `main.php` не совпадут.

### 3. Проблемы с правами доступа к кэшу

- **Симптом**: `FileSystemException: Unable to create directory: '.../var/cache/templator/xx'.`
- **Причина**: процесс PHP (`www-data`, `php-fpm`) не может создать подкаталог кэша — `FileRelatedCache::set()` вызывает `mkdir()` только при отсутствии директории и не подавляет ошибку.
- **Решение**: создайте `var/cache/` заранее и выдайте права на запись владельцу процесса: `chmod -R 775 var && chown -R www-data:www-data var`.

### 4. Проблемы с кодировкой

- **Симптом**: «кракозябры» вместо кириллицы на странице.
- **Причина**: файл шаблона сохранён не в UTF-8, либо `TemplatorConfig::$encoding` не совпадает с реальной кодировкой файлов (по умолчанию `UTF-8`).
- **Решение**: пересохраните `.php`-файлы шаблонов в UTF-8 без BOM; если проект действительно использует другую кодировку — задайте её через `setEncoding()` до заморозки конфигурации (см. [Конфигурирование шаблонизатора](09-configuration.md)).

## Что делать, если ошибка не описана

1. Очистите кэш вручную: `rm -rf var/cache/templator/*`.
2. Сверьте версии: `composer show voral/joke-templator voral/joke` — пакет требует `php ^8.5` и `voral/joke ^1.5`.
3. Откройте issue в репозитории пакета с полным текстом исключения (включая `getPrevious()`), версией PHP и минимальным шаблоном, воспроизводящим проблему.
