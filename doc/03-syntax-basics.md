# Основы синтаксиса

## Два типа конструкций

Синтаксис шаблонизатора состоит из двух непересекающихся форм:

- `{{ выражение }}` — вывод значения. Всегда результат — строка, вставленная в HTML в месте объявления.
- `{% директива %}` — управляющая конструкция: условие, цикл, наследование каркаса, вставка компонента и т.п. Часть директив блочные (имеют закрывающий тег), часть — одиночные.

Примеры вывода:

```html
{{ name }}
{{ user.profile.name }}
{{ items.0.title }}
```

Примеры директив:

```html
{% if user.admin %}Админ{% /if %}
{% foreach item in items %}{{ item.name }}{% /foreach %}
{% layout main %}...{% /layout %}
```

Разделение неслучайно: `{{ }}` компилируется в единственную строку `echo`, тогда как `{% %}` может генерировать произвольный PHP-код (циклы, ветвления, вызовы сервисов) и рекурсивно обрабатывать вложенный контент между открывающим и закрывающим тегом.

## Вывод переменных {{ }}

Внутри `{{ }}` допустим только точечный путь к значению — выражений вроде `{{ price * quantity }}` шаблонизатор не поддерживает: посчитайте значение в контроллере и передайте готовым.

```php
$response->show('pages/cart.php', [
    'name' => 'alex',
    'total' => $price * $quantity, // вычисление — в PHP, не в шаблоне
]);
```

```html
{{ name }}
{{ total }}
```

Любой вывод через `{{ }}` автоматически проходит через `htmlspecialchars()` (`ENT_QUOTES`, кодировка из `TemplatorConfig`) — это защита от XSS по умолчанию, отключить её для конкретного значения можно директивой `{% raw %}` (см. [04-directives/03-print-and-raw.md](04-directives/03-print-and-raw.md)).

## Директивы {% %}

Блочная директива состоит из открывающего тега с именем и аргументами и закрывающего тега вида `{% /имя %}` — например, `{% /if %}`, `{% /foreach %}`, `{% /layout %}`.

```html
{% if condition %}
    ...
{% elseif other %}
    ...
{% else %}
    ...
{% /if %}
```

```html
{% foreach item in items %}
    {{ item.name }}
{% /foreach %}

{% foreach key, value in map %}
    {{ key }}: {{ value }}
{% /foreach %}
```

Одиночные директивы закрывающего тега не имеют: `{% csrf %}`, `{% include css /style.css head %}`, `{% defer page.title %}`. Полный список — в [04-directives/00-overview.md](04-directives/00-overview.md).

## Точечная нотация

Путь вида `user.profile.name` — это последовательность ключей ассоциативного массива, а не обращение к свойствам объекта. И в скомпилированном коде, и в режиме интерпретации каждый сегмент трактуется как ключ массива (`$context['user']['profile']['name']`), поэтому для точечного доступа передавайте вложенные данные массивами, а не объектами:

```php
$response->show('pages/profile.php', [
    'user' => [
        'profile' => ['name' => 'Alex'],
    ],
    'items' => [
        ['title' => 'Первый'],
        ['title' => 'Второй'],
    ],
]);
```

```html
{{ user.profile.name }}
{{ items.0.title }}
```

Если в цепочке передать объект вместо массива, компиляция сгенерирует обращение к нему как к массиву и PHP выбросит ошибку во время выполнения шаблона — точечная нотация рассчитана именно на массивы.

Поведение при отсутствующем ключе различается по режимам:

- **В скомпилированном шаблоне** (обычный путь исполнения через `includeFile()`) отсутствующий ключ ничем не защищён — генерируется прямой доступ `$context['a']['b']`, и если ключа `b` нет, PHP выдаст предупреждение о неопределённом индексе, а значением станет `null`.
- **В режиме интерпретации** (`render()`, см. ниже) отсутствие ключа на любом шаге пути тихо возвращает значение по умолчанию (для `{{ }}` — пустая строка) без ошибок.

## Компиляция vs Интерпретация

У шаблонизатора два независимых способа обработки AST, каждый обработчик директивы реализует оба метода:

- **`compile()`** — генерирует PHP-код, который сохраняется в файловый кэш и затем подключается через `include`. Это основной и единственный путь, которым реально пользуется `TemplateEngine::includeFile()`/`compileFile()`/`compileString()`.
- **`render(NodeInterface $node, NodeProcessorInterface $processor, array $context): string`** — исполняет узел "на лету" и сразу возвращает готовую HTML-строку, без промежуточного PHP-файла. Реализован интерфейсом `NodeHandlerInterface`, но публичного метода `TemplateEngine`, который запускал бы весь шаблон в этом режиме, нет — `render()` актуален прежде всего при написании собственных обработчиков и в тестах.

Директивы, работающие с содержимым файлов и внешним состоянием — `layout`, `component`, `include`, `defer` — поддерживают **только компиляцию**: их метод `render()` выбрасывает `RenderingException('Not implemented yet.')`. Директивы `if`, `foreach`, вывод `{{ }}`/`{% raw %}` и `csrf` работают в обоих режимах. На практике для рендеринга страниц через `TemplatedResponse::show()` эта разница не важна — используется только компиляция; про режим интерпретации нужно помнить, если вы пишете собственный `NodeHandlerInterface` (см. [10-extending/01-custom-directive.md](10-extending/01-custom-directive.md)) и обязаны реализовать оба метода.
