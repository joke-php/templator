# Встроенные переменные шаблонизатора

## Назначение

Помимо данных, которые разработчик явно передаёт в `show()`/`includeFile()`, каждый скомпилированный шаблон получает
набор служебных PHP-переменных «бесплатно» — механизмом `extract()` над массивом, собираемым `TemplateEngine` по стеку
вложенности рендеринга. Ниже — точный список, откуда берётся каждая переменная и в какой момент она перестаёт быть
доступна.

## Сводная таблица переменных

| Переменная          | Тип                   | Область видимости                                                     | Откуда берётся                                                                          |
|---------------------|-----------------------|-----------------------------------------------------------------------|-----------------------------------------------------------------------------------------|
| `$engine`           | `TemplateEngine`      | Везде, всегда                                                         | Базовый кадр стека, задаётся один раз в конструкторе `TemplateEngine`                   |
| `$container`        | `ServiceContainer`    | Везде, всегда                                                         | Тот же базовый кадр                                                                     |
| `$components`       | `ComponentCollection` | Везде, всегда                                                         | Тот же базовый кадр (используется компилированным кодом `{% component %}`)              |
| `$response`         | `TemplatedResponse`   | Везде, где рендеринг запущен через `TemplatedResponse::show()`        | Добавляется в `show()` как `extraEngineContext = ['response' => $this]`                 |
| `$context`          | `array`               | Везде                                                                 | Второй аргумент `show()`/`includeFile()` — данные, которые вы сами передали             |
| `$component`        | `BaseComponent`       | Только внутри шаблона текущего компонента (и его собственных include) | Добавляется в `BaseComponent::compile()` при рендеринге шаблона компонента              |
| *(нет `$__layout`)* | —                     | —                                                                     | На деле это **ключ `__layout` внутри `$context`**, а не отдельная переменная — см. ниже |

## Подробное описание каждой переменной

### $engine, $container, $components

Все три задаются один раз в конструкторе `TemplateEngine` как базовый кадр внутреннего стека контекста и никогда не
удаляются — поэтому доступны в абсолютно любом шаблоне, включая каркасы и компоненты:

```php
{{ engine.templatePath }} <!-- не сработает: это НЕ точечный путь к контексту, а PHP-объект -->
```

Точечная нотация `{{ }}` работает только с `$context`, поэтому `$engine`/`$container`/`$components` используются
исключительно внутри PHP-кода, который генерируют директивы (`{% component %}` компилируется в
`$components->get(...)`), — в обычном шаблоне напрямую к ним не обратиться иначе, кроме как через собственную
директиву (см. [Создание собственных директив](10-extending/01-custom-directive.md)).

### $response

Экземпляр `TemplatedResponse`, из которого запущен рендеринг: даёт доступ к `$response->builder` (заголовок страницы,
CSS/JS) и `$response->engine`/`$response->container`. Именно на нём построены `{% include %}` (
`$response->builder->css->addToBody(...)`) и `{% component %}` (`$component->compile($engine, $response)`). Если вызвать
`$engine->includeFile()` напрямую, минуя `TemplatedResponse::show()`, переменной `$response` не будет — и любая
директива, использующая её, упадёт с ошибкой уровня PHP (`Undefined variable`).

### $context

Массив, который вы явно передали вторым аргументом:

```php
$response->show('pages/profile.php', ['user' => $currentUser]);
```

```html
<p>{{ user.name }}</p> <!-- $context['user']['name'] -->
```

Это не данные сессии и не запрос — только то, что разработчик решил передать. Точечная нотация читает исключительно
ключи массива (см. [Безопасность шаблонов](11-security.md) о рисках передачи туда целых моделей).

### $component

Доступен только внутри `template.php` самого компонента (и файлов, которые он, в свою очередь, подключает):

```php
class ClockComponent extends BaseComponent
{
    public function getTime(): string { return date('H:i'); }
}
```

```html
<!-- templates/default/components/vasoft/clock/default/template.php -->
<span class="clock">{{ time }}</span>
<!-- или напрямую через объект компонента -->
<span class="clock"><?= $component->getTime() ?></span>
```

За пределами шаблона компонента (в родительской странице) переменная `$component` не определена.

### __layout — не переменная, а ключ контекста

`LayoutHandler` не создаёт переменную `$__layout`, а вызывает
`$engine->includeFile($layoutFile, ['__layout' => ['content' => ..., 'css' => ..., 'js' => ...]], 0)` — то есть
`__layout` становится ключом **внутри `$context`** каркаса. Обращаться к нему нужно точечной нотацией, как к любому
обычному значению контекста:

```html
<!-- templates/default/layouts/main.php -->
<link rel="stylesheet" href="{{ __layout.css }}">
<body>
{% raw __layout.content %}
</body>
<script src="{{ __layout.js }}"></script>
```

Подробности — [Директива layout](04-directives/04-layout.md).

## Область видимости

Реализовано как стек кадров: каждый вызов `includeFile()` объединяет верхний кадр стека с собственным
`extraEngineContext` и проталкивает результат, а по завершении (в `finally`) снимает его обратно. Отсюда правило
наследования: `{% include %}`/`{% component %}`/`{% layout %}` **всегда** видят всё, что видел родитель, плюс своё
добавление (`component` — только у компонента, `__layout` — только внутри `$context` каркаса). Ничего из дочернего кадра
наружу, в родителя, не «протекает».

## Best Practices

- Не используйте `$container`/`$components` внутри шаблонов страниц напрямую — это ломает разделение вида и логики; их
  прямое назначение — компилированный код встроенных директив.
- Передавайте нужные данные явно через `$context`, а не полагайтесь на то, что «где-то выше» была передана нужная
  переменная — компонент, вызванный из другого места, может её не получить.
- Ошибка `Undefined variable $response` почти всегда означает, что шаблон подключён в обход
  `TemplatedResponse::show()` — проверьте точку входа рендеринга.
