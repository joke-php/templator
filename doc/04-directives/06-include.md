# Директива {% include %}

## Назначение

Регистрация CSS/JS-файла в сборщике страницы (`PageBuilder`), чтобы он попал в `<head>` или в конец `<body>` итогового HTML. Директива предназначена только для подключаемых файлов страницы — вставки одного шаблона в другой она не выполняет.

## Синтаксис

```
{% include type filename [position] %}
```

Аргументы позиционные, разделены пробелом (не именованные атрибуты вида `type="css"`):

- `type` — обязательный, равно `css` или `js`; любое другое значение (или отсутствие аргумента) даёт `RequiredParameterException`.
- `filename` — обязательный, **путь к переменной контекста** в точечной нотации (та же логика, что у `{{ }}`), а не строковый литерал пути. `{% include css style %}` компилируется в `$response->builder->css->addToBody($context['style'])` — значение `$context['style']` должно уже содержать путь к файлу согласно правилам `AssetFileManager` фреймворка
- `position` — необязательный, `head` или `body` (по умолчанию `body`); любое иное значение молча трактуется как `body`.

## Примеры использования

### Подключение CSS в `<head>`

```php
$response->show('templates/index.php', ['themeCss' => '/assets/theme.css']);
```

```html
{% include css themeCss head %}
```

### Подключение JS в конец `<body>`

```php
$response->show('templates/index.php', ['appJs' => '/assets/app.js']);
```

```html
{% include js appJs %}
```

### Подключение ресурсов каркаса (реальный пример из демо)

```html
{%include css __layout.css%}
{%include js __layout.js%}
```

Здесь `__layout.css`/`__layout.js` — вложенные ключи переменной `$__layout`, которую сам `{% layout %}` заранее наполняет вычисленными путями к файлам темы (см. [Каркасы](04-layout.md)).

## Механизм работы

Директива компилируется в прямой вызов `$response->builder->css` или `->js`, метод `addToHead()`/`addToBody()`. Внутри `AssetCollection` файлы хранятся в массиве, **проиндексированном по URL** — повторная регистрация того же пути просто обновляет запись без дублирования HTML-тега. Есть одно исключение из порядка: если файл уже зарегистрирован в `head`, последующий вызов `addToBody()` для того же URL не переносит его в `body` — приоритет остаётся у `head`. Директива работает только в режиме компиляции; `render()` выбрасывает `RenderingException`.

## Отличие от {% component %}

`include` — статическая регистрация ресурса без логики и контекста. `{% component %}` — класс со своим жизненным циклом (`execute → beforeRender → includeFile`), собственными данными для шаблона и опциональным визуальным представлением (см. [Компоненты](05-component.md)).
