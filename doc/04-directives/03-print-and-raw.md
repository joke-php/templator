# Вывод данных: {{ }} и {% raw %}

## Назначение

Два способа вывести значение из контекста в шаблон: `{{ }}` — с автоматическим экранированием HTML, `{% raw %}` — без
него.

## Экранированный вывод {{ }}

### Синтаксис

```html
{{ путь }}
```

### Как работает

Компилируется в `<?= htmlspecialchars((string)$значение, ENT_QUOTES, $кодировка); ?>`. Экранирование применяется всегда
и безусловно — отключить его для `{{ }}` нельзя, для вывода без экранирования используется отдельная директива
`{% raw %}`. Это защита от XSS по умолчанию: любые данные, включая пользовательский ввод, безопасно попадают в HTML.

### Примеры

```php
$response->show('pages/profile.php', [
    'name' => 'Alex',
    'user' => ['email' => 'alex@example.com'],
]);
```

```html
{{ name }}
{{ user.email }}
```

Аргумент `{{ }}` — только точечный путь к значению в контексте. Выражения вида `{{ price * quantity }}` не
поддерживаются: вычисление нужно выполнить в контроллере и передать готовый результат.

### Что экранируется

`htmlspecialchars()` вызывается с флагом `ENT_QUOTES`, то есть заменяются все пять спецсимволов: `&` → `&amp;`, `<` →
`&lt;`, `>` → `&gt;`, `"` → `&quot;`, `'` → `&#039;`. Кодировка берётся из `TemplatorConfig::$encoding` (по умолчанию
UTF-8).

## Сырой вывод {% raw %}

### Синтаксис

```html
{% raw путь %}
```

Это одиночная директива без парного закрывающего тега (в отличие от `{% if %}`/`{% foreach %}`) — она не оборачивает
блок контента, а сама заменяется значением по указанному пути. Компилируется в `<?= $значение ?>` — без каких-либо
преобразований.

### Когда использовать

- Вывод содержимого каркаса (`{% raw __layout.content %}` внутри layout).
- Вставка HTML, уже подготовленного и провалидированного на сервере.
- Разметка, полностью контролируемая приложением, а не пользователем.

### Предупреждение о безопасности

`{% raw %}` полностью отключает защиту от XSS для этого значения. Если путь ведёт к данным, которые прямо или косвенно
пришли от пользователя (комментарий, профиль, поле формы), вывод через `{% raw %}` — прямая XSS-уязвимость: браузер
выполнит любой `<script>`, вставленный туда. Используйте `{% raw %}` только для контента, который приложение само
сгенерировало или пропустило через санитайзер HTML. Подробнее — [Безопасность шаблонов](../11-security.md).

## Сравнение {{ }} и {% raw %}

| Конструкция | Экранирование | Когда использовать                                       |
|-------------|---------------|----------------------------------------------------------|
| `{{ }}`     | Да            | По умолчанию для любых данных, особенно пользовательских |
| `{% raw %}` | Нет           | Только для доверенного, заранее проверенного HTML        |

## Примеры из практики

**1. Вывод имени пользователя** (данные потенциально из формы регистрации — экранируем):

```html
<h1>Привет, {{ user.name }}!</h1>
```

**2. Вывод HTML-контента статьи** (текст прошёл через серверный санитайзер перед сохранением):

```php
$response->show('pages/article.php', [
    'title' => $article->title,
    'bodyHtml' => $sanitizedHtml, // очищено HTML Purifier при сохранении статьи
]);
```

```html
<h1>{{ title }}</h1>
<div class="article-body">{% raw bodyHtml %}</div>
```

**3. Смешанный случай** — заголовок и имя автора экранируются, а тело статьи выводится как есть:

```html

<article>
    <h1>{{ title }}</h1>
    <p>Автор: {{ author.name }}</p>
    <div>{% raw bodyHtml %}</div>
</article>
```

Правило простое: `{{ }}` — вариант по умолчанию для всего; `{% raw %}` — точечное исключение только там, где источник
HTML доверенный.
