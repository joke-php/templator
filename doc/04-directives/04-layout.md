# Директива {% layout %}

## Назначение

Оборачивает содержимое текущего шаблона в общий каркас (header, footer, обвязку страницы), чтобы не дублировать разметку
в каждом файле. Каркас — обычный PHP/HTML-файл темы, содержимое дочернего шаблона подставляется в него через
`$__layout['content']`.

## Синтаксис

```html
{% layout имя_каркаса %}
...контент...
{% /layout %}
```

Имя каркаса — **без кавычек**, обычный идентификатор (`main`, `note`), который транслируется напрямую в имя файла
`имя_каркаса.php`. Строка в кавычках (`'main'`) не сработает — символы кавычек попадут в путь к файлу буквально, и файл
не будет найден.

## Примеры использования

### Создание базового layout (каркаса)

Реальный пример из демо-темы, `templates/default/layouts/main.php`:

```html

<fieldset>
    <legend>{% block.name %}</legend>
    {%raw __layout.content%}
    {%include css __layout.css%}
    {%include js __layout.js%}
</fieldset>
```

- `{%raw __layout.content%}` — место вставки контента дочернего шаблона. Используется именно `raw`, а не `{{ }}`, потому
  что содержимое — это уже готовый HTML, и экранирование испортило бы разметку.
- `{%include css __layout.css%}` / `{%include js __layout.js%}` — подключение файлов стилей и скрипта каркаса. Пути
  `__layout.css`/`__layout.js` формируются автоматически рядом с файлом каркаса (`layouts/main.css`,
  `layouts/main.js`) — подробнее в [Подключаемые файлы](06-include.md).

### Использование layout в дочернем шаблоне

```html
<h1>{{ name }}</h1>
{% layout main %}
<p>Содержимое страницы для каркаса main</p>
{% /layout %}
```

Собственных «слотов» с именами (как `{% block %}` в Twig) нет — в каркас передаётся единственная переменная
`__layout.content` со всем содержимым между `{% layout %}` и `{% /layout %}`. Если нужно передать в каркас что-то ещё,
добавьте это в контекст самой страницы и обращайтесь к нему в файле каркаса через обычный `$context` — движок передаёт
его как отдельную переменную наравне с `$__layout`.

## Механизм работы

1. **Поиск файла каркаса** — `TemplateEngine::getLayoutPath()` ищет `{layoutsPath активной темы}/{имя}.php`; если файл
   не найден и активная тема не `default`, дополнительно проверяется `{layoutsPath темы default}/{имя}.php`. Если каркас
   не найден нигде — `TemplatorException: Unable to locate layout file`.
2. **Порядок обработки — сначала дочерний контент, потом каркас.** Компилятор сначала генерирует PHP-код содержимого
   между тегами `{% layout %}`/`{% /layout %}`, оборачивает его в `ob_start()`/`ob_get_clean()`, и только полученную
   строку передаёт в файл каркаса как `$__layout['content']`:

    ```php
    ob_start();
    /* ...скомпилированное содержимое дочернего шаблона... */
    $__content = ob_get_clean();
    $__layoutContext = ['__layout' => ['content' => $__content, 'css' => '...', 'js' => '...']];
    $engine->includeFile($filename, $__layoutContext, $config->defaultTtl);
    ```

3. **Подстановка** происходит через `TemplateEngine::includeFile()` — тот же механизм, что и для обычных страниц, с
   изоляцией переменных между уровнями вложенности. TTL кэша каркаса берётся из `TemplatorConfig::$defaultTtl` (по
   умолчанию 86400 секунд) и не зависит от TTL, заданного для внешней страницы в `show()` —
   см. [Конфигурация шаблонизатора](../09-configuration.md#ttl-каркаса-по-умолчанию) и [Кешированние](../08-caching.md).

Директива работает **только в режиме компиляции** — метод `render()` (интерпретация) выбрасывает
`RenderingException('Not implemented yet.')`.

## Вложенные layout

Поддерживаются: поскольку содержимое между тегами `{% layout %}`/`{% /layout %}` компилируется как обычный вложенный
узел AST, внутри него может встретиться ещё один `{% layout %}`. Пример из демо — компонент оборачивает свой шаблон в
отдельный лёгкий каркас `note` (`templates/default/layouts/note.php`, без заголовка и подключения ресурсов):

```html

<div class="variant2">
    {%layout note%}
    <h5>Вариант 2</h5>
    <p>Случайное число: {{demo}}</p>
    {%/layout%}
</div>
```

Каждый уровень вложенности независимо буферизует свой вывод и подключает свой файл каркаса, поэтому глубина вложенности
не ограничена архитектурой — она ограничена только смыслом.
