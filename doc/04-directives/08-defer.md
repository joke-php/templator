# Директива {% defer %}

## Назначение

Решает задачу, когда значение нужно вывести **раньше**, чем оно становится окончательно известным — типовой случай: `<h1>` страницы должны отражать заголовок, который устанавливает компонент, отрендеренный значительно ниже по шаблону. Обычный `{{ }}` так не может: он выводит то, что есть в контексте *в момент компиляции этой строки*, а не то, что будет установлено позже.

## Синтаксис

```
{% defer путь %}
{% defer путь raw %}
```

Одиночная директива без закрывающего тега. Первая форма выводит значение с HTML-экранированием, вторая (с флагом `raw`) — без экранирования.

## Примеры использования

### Базовый пример: динамический заголовок

Реальный пример из демо, `pages/index.php`:

```html
<h1>{%defer page.title raw%}</h1>
```

и в каркасе `templates/default/layouts/main.php`:

```html
<small>{%defer page.title%}</small>
```

Ни одна из этих строк не задаёт значение `page.title` сама — обе просто резервируют место под финальное значение. Реальное значение приходит не из `$context`, а устанавливается фреймворком автоматически (см. «Механизм работы»): любой код на странице, включая глубоко вложенный компонент, может вызвать `$pageBuilder->setTitle('Заголовок из компонента')`, и именно это значение появится во всех местах, где встретился `{% defer page.title %}`/`{% defer page.title raw %}` — независимо от того, что эти теги были скомпилированы раньше, чем отработал компонент.

### Использование флага raw

`raw` нужен, когда отложенное значение — это уже готовая разметка, а не текст:

```html
<div id="widget-summary">{% defer widgetSummary raw %}</div>
```

Без `raw` это же значение прошло бы через `htmlspecialchars()` при финальной подстановке и превратилось бы в escaped-текст вместо HTML.

## Механизм работы

Директива компилируется в вызов `DeferService::register()` (или `registerRaw()` для `raw`):

```php
<?= $response->getDeferService()->register('page.title', (string)($context['page']['title'] ?? '')); ?>
```

Значение вычисляется **немедленно**, в момент прохождения этой строки шаблона, и регистрируется в сервисе под ключом (`page.title`). Функция возвращает не само значение, а уникальный текстовый плейсхолдер (`##___DEFER___page.title##`), который и попадает в буфер вывода. Повторная регистрация с тем же ключом **перезаписывает** сохранённое значение — но не сам плейсхолдер: если тег с одним и тем же ключом встретился в нескольких местах шаблона, все они получат в буфере вывода один и тот же текстовый маркер, и все они одновременно заменятся на финальное значение.

Настоящая магия — в `TemplatedResponse::show()`. После того как вся страница (включая все вложенные компоненты) полностью отрендерена в буфер, `show()` сам вызывает:

```php
$defer->register('page.title', $this->builder->title ?? '');
$defer->registerRaw('page.title', $this->builder->title ?? '');
$body = $defer->flush($body);
```

То есть заголовок берётся из `$response->builder->title` — а его мог установить любой компонент через `$pageBuilder->setTitle()` в своём `execute()`, вызванном значительно позже места, где стоит `{% defer page.title %}`. Только после этого `flush()` одним проходом (`strtr()`) заменяет плейсхолдеры на итоговые значения: обычные — с `htmlspecialchars`, `raw` — как есть.

Директива работает **только в режиме компиляции** — `render()` бросает `RenderingException('Not implemented yet.')`. `DeferService` — синглтон в рамках запроса, его реестр очищается методом `clean()` после каждого `show()`.

## Типовые сценарии

**1. Заголовок `<h1>` из глубоко вложенного компонента.** Страница печатает `{% defer page.title %}` в начале разметки; конкретный компонент, отрендеренный ниже, вызывает `$pageBuilder->setTitle('...')` в своём `execute()` — итоговый заголовок подставится в уже пройденное место благодаря отложенной замене в `show()`.

**2. Несколько мест вывода одного и того же значения** — например, заголовок одновременно в `<h1>` и в `<small>` каркаса (как в демо): достаточно продублировать `{% defer page.title %}` в обоих местах, значение будет одинаковым в обоих после `flush()`.
