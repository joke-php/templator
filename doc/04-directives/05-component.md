# Директива {% component %}

## Назначение

Подключение переиспользуемых виджетов/компонентов (карточка дня, случайное число, блок навигации и т.п.) как
самостоятельных классов со своей логикой и своим шаблоном — без копирования разметки по страницам.

## Синтаксис

```
{% component vendor:name [templateName] [options] %}
```

Аргументы разделяются пробелами (`preg_split('/\s+/', ...)`), обязателен только первый:

- `vendor:name` — уникальное имя компонента в формате `вендор:имя`, под которым он зарегистрирован в
  `ComponentCollection`. Обязательный аргумент.
- `templateName` — необязательное имя шаблона компонента (поддиректория внутри его каталога, по умолчанию `default`).
  Если указано, компилируется в вызов `$component->setTemplateName(...)`.
- `options` — необязательный точечный путь к переменной в контексте текущего шаблона (та же нотация, что в `{{ }}`/
  `{% if %}`), которая будет передана в `setOptions()`.

Директивы одиночные, закрывающего тега нет.

## Примеры использования

### Базовый компонент

Минимальный вызов — только имя, используется шаблон `default`:

```html
{% component vasoft:day %}
```

### Компонент с передачей данных

Опции передаются как путь к переменной контекста:

```php
$response->show('pages/index.php', [
    'randomRange' => ['min' => 10, 'max' => 99],
]);
```

```html
{% component vasoft:random variant2 randomRange %}
```

Компилируется в `$component->setOptions($context['randomRange'] ?? null)` — компонент сам решает, как интерпретировать
эти данные в своей реализации `execute()`.

### Компонент с указанием шаблона

Второй аргумент переключает поддиректорию с файлом шаблона компонента, не трогая опции:

```html
{% component vasoft:random variant1 %}
```

Это отрендерит `templates/{тема}/components/vasoft/random/variant1/template.php` вместо `.../default/template.php`.

## Механизм работы

**Поиск компонента.** `$components->get('vasoft:day')` ищет запись в `ComponentCollection` по точному имени; компонент
может быть зарегистрирован как готовый экземпляр, `class-string` или фабрика — во втором и третьем случае объект лениво
создаётся через DI-контейнер (`container->make()`). Если имя не зарегистрировано —
`TemplatorException: Component '...' not found.`

**Жизненный цикл `BaseComponent::compile()`:**

1. `execute($pageBuilder)` — выполняется всегда, готовит данные и может менять заголовок/мета страницы (`PageBuilder`).
2. Если `$templateName` пустой — на этом жизненный цикл завершается: компонент отработал только логику, без вывода (
   режим «только логика», например регистрация ресурса без разметки).
3. Резолвится каталог шаблона компонента через каскад тем (`TemplateEngine::getComponentTemplateDir()`).
4. `beforeRender($pageBuilder)` — вызывается только если есть шаблон; здесь удобно подключать CSS/JS компонента через
   `templateFile()`.
5. `includeFile()` рендерит `template.php` компонента с контекстом из `getContext()`.

**Доступные переменные внутри шаблона компонента** — всё из `getContext()` плюс автоматически добавляемая переменная
`$component` (текущий экземпляр, для доступа к его публичным данным и методам), а также сквозные `$engine`/`$container`,
общие для всей цепочки рендеринга.

Как и `{% layout %}`, директива работает **только в режиме компиляции** — `render()` бросает
`RenderingException('Not implemented yet.')`.

## Отличие от {% include %}

`{% include %}` подключает статический файл ресурса (CSS/JS) в сборщик страницы — у него нет ни логики, ни собственного
контекста, ни жизненного цикла (см. [Подключаемые файлы](06-include.md)). `{% component %}` — это класс с
бизнес-логикой (`execute()`), собственным набором данных для шаблона и опциональным визуальным представлением.

|                           | `{% include %}` | `{% component %}`                                 |
|---------------------------|-----------------|---------------------------------------------------|
| Что подключает            | Файл CSS/JS     | Класс с логикой и (опционально) шаблоном          |
| Есть ли своя логика       | Нет             | Да, `execute()`/`beforeRender()`                  |
| Свой контекст для шаблона | Нет             | Да, `getContext()`                                |
| Кэшируется отдельно       | Нет             | Да, свой TTL (`$fileTtl`, по умолчанию 86400 сек) |

Используйте `include`, чтобы подключить файл стилей/скрипта; используйте `component`, когда нужен переиспользуемый блок
с логикой и своим шаблоном.
